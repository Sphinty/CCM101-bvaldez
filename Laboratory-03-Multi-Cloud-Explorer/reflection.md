# Reflection: Cloud Evaluation Team Mission

**1. Which cloud platform impressed you the most?**
Honestly, GCP surprised me the most. I went into this expecting AWS to dominate every category since it's the name everyone hears about, but GCP's focus on AI and machine learning really stood out. Learning that Google built their own hardware (TPUs) just to speed up AI workloads made me realize cloud providers don't just compete by being the biggest. Some of them win by going deep into one thing and doing it really well. The fact that Google also created Kubernetes and still runs the most mature version of it (GKE) made that point even clearer.

**2. What similarities exist among AWS, Azure, and GCP?**
Once I got past the different names and dashboards, it became obvious that these three platforms are basically doing the same job. They all have a virtual machine service, an object storage service, and some form of identity and access management. EC2, Azure VMs, and Compute Engine are really just the same idea with different branding. Same goes for S3, Blob Storage, and Cloud Storage. They all use pay as you go pricing, all have global data centers, and all offer managed databases and Kubernetes support. So at the core, it's less about which one has better tech and more about which ecosystem fits the client.

**3. How do business requirements influence cloud platform selection?**
This was probably the biggest takeaway for me. There's no single best cloud provider. It really depends on who's asking. A startup cares about saving money early on, so AWS's credits and flexible pricing make sense. A university that already runs on Microsoft tools isn't going to want to relearn everything, so Azure is the obvious fit. And a company doing heavy AI research needs GCP's specialized hardware. It made me realize that picking a cloud platform isn't about personal preference. It's about matching the tool to the actual problem in front of you.

**4. What did you learn from acting as a Cloud Solutions Consultant?**
Doing this made me think more like a consultant instead of just a student following instructions. I had to actually look at each client's situation, their budget, their existing systems, their goals, before recommending anything. It's easy to just say use AWS because it's the biggest one, but that's not really solving the client's problem. This mission taught me to ask what does this specific business actually need before jumping to a recommendation.

**5. How has your GitHub Cloud Computing Portfolio improved after completing this mission?**
My portfolio looks a lot more professional now. Before this, I wasn't really used to writing structured technical documentation. Now I've got comparison tables, clear explanations, and actual reasoning behind each recommendation, all formatted properly in Markdown. It feels less like a school assignment and more like something I could actually show a potential employer or client.
